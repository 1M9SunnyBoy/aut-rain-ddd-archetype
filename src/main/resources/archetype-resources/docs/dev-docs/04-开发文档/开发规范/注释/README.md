${hash} 注释规范

版本：v1.0；更新：2026-11-04。适用于脚手架维护及生成项目的前端、后端、SQL 和脚本。

${hash}${hash} 1. 基本原则

注释解释接口契约、业务含义、设计原因和边界条件，不逐行翻译代码。修改实现时同步维护注释，过时或与实现矛盾的注释视为缺陷。优先使用清晰命名，简单 getter、setter 和直观赋值无需重复说明。

作者字段使用 author，不使用容易与认证混淆的 auth。作者标记不替代 Git 的实际提交记录。第三方源码、上游 SQL 的许可证和原作者声明必须保留，不得覆盖原有署名。

${hash}${hash} 2. 文件头

手写源码、测试、SQL 和脚本的文件头说明 description（职责）、author（作者）、created（创建日期，YYYY-MM-DD）。日期记录文件首次创建时间，不维护最后修改时间，不随重新生成、构建或普通修改刷新；历史日期无法确认时不得伪造。示例日期仅作格式演示。

Java 使用文件顶部普通块注释，避免把文件头误挂到 package 或 import 上；公共类型另写 JavaDoc。TypeScript/TSX、CSS 同样可使用块注释：

```java
/*
 * description: 项目创建请求的数据契约。
 * author: 作者名称
 * created: 2026-11-04
 */
```

Shell 文件必须保留 shebang 在第一行，文件头写在其后；PowerShell 使用注释块或井号注释；SQL 使用 -- 注释；YAML 使用井号注释；XML 声明仍位于首行。Markdown 在必要时使用可见元信息或 HTML 注释，不重复堆积文件头。

严格 JSON 不支持注释，不添加伪造的作者业务字段。锁文件、二进制、构建产物、第三方文件和工具维护的生成文件不强制添加文件头。不得为添加注释修改已部署 Flyway 迁移，以免改变校验和。

模板中的 Velocity 指令仍置于过滤文件所需位置；需要输出的井号、美元符号按脚手架转义约定处理，生成后不得残留模板指令。此规范约束后续新增和维护，历史文件按实际修改逐步补齐，不表示现有文件已经全部补齐文件头。

${hash}${hash} 3. 接口与公共方法

对外 HTTP API、跨模块接口、公共业务方法必须说明用途、参数约束、返回语义和可预期异常。涉及权限、幂等、事务或副作用时明确约定。HTTP 接口还应记录路径、方法、业务响应码与 HTTP 状态；文件下载、分页、空结果等特殊行为不能省略。

Java 使用 JavaDoc 的 @param、@return、@throws；前端公共函数和 Hook 使用兼容 TSDoc 的说明，并明确异步、取消、缓存和资源释放职责。类型系统已经表达的类型不重复堆砌。不存在的权限校验、重试或事务机制不得写成已实现能力。

```java
/**
 * 查询指定项目的详情。
 *
 * @param projectId 项目 ID，不能为空
 * @return 项目详情；不存在时抛出业务异常，不返回空对象
 * @throws BusinessException 项目不存在或调用方无权访问
 */
```

该片段是契约格式示例，项目应按真实行为填写，不据此默认模板已有项目查询或鉴权功能。

${hash}${hash} 4. 核心代码

复杂业务规则、状态流转、锁顺序、幂等处理、重试补偿、性能取舍和兼容方案应在相关代码附近说明原因及约束。引用需求、问题单或协议时提供稳定标识；临时方案说明移除条件。

```java
// 按项目 ID 升序加锁，与删除流程保持一致，避免并发批量操作形成循环等待。
```

TODO/FIXME 应包含负责人、具体问题和跟踪项或完成条件。禁止提交大段废弃代码注释，历史实现通过 Git 查询；注释中不得包含密码、Token、真实个人信息。

${hash}${hash} 5. 对象属性

请求/响应 DTO、持久化对象、领域对象及前端公共数据类型的重要属性说明业务含义、单位、范围、可空性和默认值。状态值说明允许值及对应含义；金额写明币种或单位、精度；时间区分自然日期与带时区时间点；ID 明确标识对象。敏感字段说明输出限制。

Java record 优先在类型 JavaDoc 中用 @param 描述组件，保证生成的 API 文档可读；普通字段使用字段 JavaDoc。TypeScript 属性使用紧邻字段的文档注释。

```java
/**
 * 项目创建请求。
 *
 * @param name 项目名称，必填，最多 100 个字符
 * @param budget 预算金额，单位元，允许为空，最多两位小数
 */
public record CreateProjectRequest(String name, BigDecimal budget) {}
```

```typescript
interface CreateProjectRequest {
  /** 项目名称，必填，最多 100 个字符。 */
  name: string;
  /** 预算金额，单位元；十进制字符串，最多两位小数；null 表示未填写。 */
  budget: string | null;
}
```

示例字段约束须由实际校验和接口序列化落实，注释本身不产生校验或类型转换。SQL 表、列 COMMENT 与对象属性说明保持一致；已部署字段说明变更通过新增迁移完成。

${hash}${hash} 6. 评审要求

- 文件职责清楚，适用文件包含作者信息，日期来源真实。
- 接口注释与实现、校验、响应码和测试一致。
- 核心逻辑解释原因及边界，没有无意义的逐行注释。
- 属性单位、可空性、状态含义和时间语义明确。
- 保留第三方署名与许可证，不改写已部署迁移，不破坏文件格式。

这些是人工评审要求，当前不宣称已有自动注释覆盖率或完整性检查。
